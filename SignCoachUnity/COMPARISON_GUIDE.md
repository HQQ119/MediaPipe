# 当前版本：评分档位 v2.1（2026-11-15）

默认使用“入门练习”，也可以切换“精细对照”。切换后重新开始比较。两档共用完全相同的特征、执行手、精细DTW对齐路径、原始距离与质量限制，只调整沿该路径的分数换算。下方v2说明中的旧得分公式对应精细档；与本节冲突处以本节为准。

- 精细档：`score_g = 100 / (1 + r)`，其中 `r = 分组距离 / 该组容差`。差异等于配置容差时只有50分，对小偏差较敏感。
- 入门档：`score_g = 100 / (1 + k*r*r)`，`k = 1/0.85 - 1`。零差异100分，差异达到容差时85分；这是明确的工程尺度选择，不是经教师样本验证的合格线。极大差异仍接近0，并非给总分加常数。
- 同一路径上按帧平均各项得分，再按原组权重合成；双手模式继续保留15%的双手相对位置分，最后乘以原动静一致系数。
- 报告新增 `settings.ScoringProfile`（0入门、1精细）、`settings.IntroductoryToleranceCredit`、`scoring_loss`；`algorithm_version=2.1`。`similarity = 100*(1-scoring_loss)*motion_presence_score/100`。这只扩展比较结果报告，不改变采集TCP或录制JSONL结构。
- DTW的raw_distance、normalized_distance、path仍采用精细档距离。入门分不能再用 `100*(1-dtw.normalized_distance)` 计算；可按上述scoring_loss或分项复算。
- 中途长缺失、低覆盖、错误执行手、静止手冒充挥动等限制不变。参考质量不足仍单独提示，不能据此评价用户动作对错。

当前容差与权重沿用v2，未改模型、MediaPipe推理、原始录制、左右手标签或镜像规则。两档是动作几何对照工具，尚未完成手语教学评分校准。

# 当前实现：动作比较 v2（2026-11-15）

v2复用现有读取、特征、DTW和界面，修正执行手误配、归一化基准不一致及分数组量纲问题。下面原第四阶段说明保留为历史记录；冲突处以本节为准。原JSONL、TCP、模型推理与左右标签均不修改。

## 怎么使用

1. 选择词汇及本次练习文件。默认按参考片段的几何运动情况建议执行手，并且只对齐同名左右标签。
2. 两边标签不一致时停止给分，提示参考及练习标签。确认实际使用不同手时，可以明确选择“手动配对（单手）”，例如参考Right、练习Left；报告会写明这一选择，不会交换原始标签。
3. 双手配合、包括一只手作为静态支撑的动作，请明确选择“双手分别比较”。自动推荐依据几何变化，不能理解手语语义，不能保证选对支撑手。
4. 只有明确知道来源画面被水平镜像时才选择还原镜像。只在算法副本中还原x，不会自动搜索哪个方向分数最高，原文件和模型标签保持不变。
5. 结果页显示总分、六个分项、执行手对应关系与数据覆盖。切换文件或设置后重新点击开始比较。

## 计算与质量

- 手型在每只手自身的掌部坐标系中描述，关节角、指尖距与局部点位置按掌尺度归一化；掌朝向保留并单独比较，避免旋转同时压低局部手型分。
- 每只手使用自身有效段掌中心中位数、掌尺度中位数作为轨迹基准。另一只手出现或消失不改变此基准。双手模式另比较两手相对位置，避免独立居中抹掉配合关系。
- 轨迹仅使用图像平面的x/y；MediaPipe wrist-relative z用于局部几何，不冒充相机空间的前后平移深度。
- 有效区间是所选执行手首次至末次可用帧，不是语义识别出的动作起止。入镜前后帧单独统计并排除；中途丢失、重复标签和采集时间断层仍统计和提示。并未自动剔除所有准备姿势或无关动作。
- 插值仍限有两端锚点、至多3帧、锚点相隔至多150ms。长缺失不补零、不伪造手。
- 可靠覆盖在所选执行手的有效区间内计算。低于70%提示有限数据；低于50%、中途缺失跨度超过500ms或任一段参与不足5帧时，界面暂不评分。报告保留距离供诊断，调用方须同时检查score_available。

每组距离先换算为有界损失 `loss = d / (d + tolerance)`。0差异损失0，差异等于工程容差时损失0.5，不是教学合格线。

| 分项 | 默认权重 | 工程容差 |
| --- | ---: | --- |
| 关节角 | 25% | 15度（由当前图像几何估计） |
| 指尖距 | 15% | 0.35掌尺度 |
| 局部手型 | 20% | 0.20掌尺度 |
| 掌朝向 | 15% | 30度 |
| 轨迹 | 20% | 1掌尺度 |
| 相对尺度 | 5% | log尺度差0.20 |

单手仅比较选定的对应手；双手模式的帧损失为六项加权损失的85%加上双手相对位置损失的15%。缺少一侧所需数据时计显式损失，双方都无该标签时不当零坐标比较，整体覆盖不足另阻止给分。

DTW在归一化序列进度窗口0.25内求最小累计损失，并限制连续水平/垂直重复。重复上限为max(3, ceil(长序列帧数/短序列帧数))，最多32；采用包含方向和连续次数的动态规划状态，保证约束下最优，不是先求无约束路径再删点。约束方法参考[Müller/FMP](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S2_DTWvariants.html)。未找到可达路径时明确报错，不静默放宽。仍保留原始帧索引与时间戳。

`base_score = 100 * (1 - path_mean_loss)`。

为避免“开掌静止”仅凭手型相同获得高挥动分，另检查两段的动静状态：几何运动指标均低于0.35时系数为1；否则系数为min(1, 较小运动指标/0.35)。运动指标来自按掌尺度计量的中心范围及角度/朝向变化；它是工程策略，不是语言语义分类。

`score = base_score * motion_agreement`。六个分项、双手关系（适用时）、动静一致性均显示，能够追溯总分。旧SimilaritySigma字段仅保留旧调用兼容，v2不使用指数转分。

## 适用范围

这些容差、动态门限和权重尚无手语教师标注数据的统计校准，分数是所选手部动作的工程相似度，不是手语正确率。当前参考只有少量采样图像，原始时基和镜像仍可能未知；相机视角、遮挡和原始识别错误也会影响结果。算法回归通过不等于真人手语教学评分通过。

# 第四阶段：动作序列比较

本阶段比较手部几何与运动序列，不判断中文手语语义，不输出手语正确率。
现有两份 hello 录制均为**未审核测试录制**；目录名不能证明其中的动作是“你好”。

## 运行

可以离线比较已有文件，不必启动 Python 或摄像头：

```powershell
& 'D:\测试项目\unity\SignCoachUnity\Build\SignCoachLite.exe' `
  -recordingRoot 'D:\测试项目\unity\SignCoachUnity\data\reference'
```

点击右上角“动作序列比较”，选择 A/B 录制后“开始比较”。同一份也可同时选为 A 和 B。
计算在后台 Task 执行，主线程继续处理界面及原有接收/绘制。可以取消或返回追踪/录制；有未保存录制时不能打开比较。
“保存比较报告”在数据目录旁边的 `data/comparisons/` 新建带时间和随机后缀的 JSON，不覆盖录制。
窗口可滚动：来源和质量、距离/相似度、A/B 原始时间轴、成本矩阵/路径、高差异片段。
橙色为缺失或标签歧义，红色为超过工程差异阈值的局部距离，不代表动作做错。矩阵使用参与比较帧序号，时间轴保留原始缺失位置。
本阶段没有并排骨骼回放，可返回原有实时骨骼界面。

## 数据类型

只读 metadata，不修改任何原始标记：

| 类型 | 读取规则 |
| --- | --- |
| 未审核测试录制 | 默认类型，包括现有 unverified_test 和无法确认的 metadata |
| 已审核标准示范（metadata 声明） | verification_status=verified_reference，且 source_reference 非空 |
| 用户练习录制 | source=user_practice 或 verification_status=user_practice |

“已审核”是文件已有的人工声明，程序不独立认证示范或验证链接。没有自动升级、审核或编辑原始标记的功能。

## 特征与归一化

代码位于 `Assets/Scripts/Comparison/`，与 TCP、显示层独立。`SequenceComparer.Load` 复用第三阶段完整读取与 metadata 校验。

1. 按 handedness 和 landmark id 取手与点，忽略数组顺序。两只手同标签时，该标签不可用，不按位置或分数挑一只。
2. 计算坐标为 `(x, 0.75*y, 0.35*z)`。0.75 对应本项目640×480图像比例，0.35是降低相对深度影响的工程参数，均可配置。
   这不是经标定的三维坐标，下述角度是几何近似，不是解剖测量。
3. 每手掌尺度为手腕到点5/9/17的长度均值。所有点相对手腕、除以当前掌尺度；不旋转回统一朝向，因此保留掌旋转与手指形态。
4. 掌中心为0/5/9/13/17均值。全序列以有效掌尺度中位数归一化轨迹；首次有效双手中心均值作为共同起点，单手用首次可用掌中心。
   两手共享参考起点，保留双手相对布置与后续轨迹；当前掌尺度与序列尺度之比保留相对尺度变化。
5. 每手特征：15个三点关节角（除以π）、10个指尖两两距离、21×3手腕相对点、手腕到点9方向与掌面法向共6维、3维中心轨迹、1个相对尺度。

全程只生成独立数组，不改原始 JSONL、镜像坐标或标签。共同平移/统一缩放不变性以及保留旋转差异均有测试，不保证任意相机角度与体型下完全等价。

## 缺失与质量

分别报告原始有手检出率、标签可区分且几何有效的可靠帧率、参与帧数、插值手数、排除帧数，不能将检出率当标签可靠性。

- 同名手缺失前后都有可靠锚点、不超过3帧、两锚点相距不超过150ms，才逐点线性插值。
- 端部、长缺失或无两侧锚点不插值；不使用零坐标填充。整帧无特征时排除，单手可用时仍保留。
- 按同名标签比较。双方都缺同一标签时不当零特征计算；仅一方缺失时使用显式代价，默认1。
- 单左手对单左手不要求右手；没有共同活跃标签时明确拒绝，不交换左右手。
- 活跃手是该标签可用帧达到可靠帧数10%的手，仅用于质量区间及可比性判断，不改标签。
- 可靠率低于70%、任一活跃手缺失/歧义超过500ms、采集时间断层超过500ms、或歧义帧超过20%时标低质量。

统计使用插值前可用性，插值不会消除低质量标记。区间时长为末帧时间戳减首帧，单个缺失帧跨度0但数量仍保留。
上述值是可配置工程策略，没有手语语义阈值依据。低质量默认隐藏相似度数字、提示重录，明确勾选后才展示有效段诊断值。
JSON报告保留计算值、低质量标记、覆盖率和区间，不能把数值当完整动作评价。

## 距离、DTW、相似度

每个匹配手按角度、指尖、相对点、掌方向、中心轨迹分组计算RMS差；尺度差用 `abs(log(scaleA/scaleB))`。
默认权重依次为 `0.25, 0.15, 0.20, 0.15, 0.20, 0.05`，按总权重归一化，避免63维点位置淹没15维角度。
帧距离为有数据或单边缺失标签的代价均值。报告另有缺手配对数，分组均值只统计双方都存在的匹配手，不含缺失代价。

经典DTW递推与回溯参考 [Müller/FMP DTW 配套教材](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S2_DTWbasic.html)。
实现先最小化累计成本，再除以路径长度，不声称直接最小化路径平均成本。

```text
D[i,j] = C[i,j] + min(D[i-1,j-1], D[i-1,j], D[i,j-1])
raw_distance = D[N-1,M-1]
normalized_distance = raw_distance / path_length
similarity = 100 * exp(-normalized_distance / sigma)
```

默认sigma=0.5，可在界面配置。非负距离保证0–100且距离越小值越大。这是未校准工程映射，不是手语正确率，改变sigma会改变数字。
默认DifferenceThreshold=0.35仅供高差异显示：路径上按原始帧平均局部距离，超过阈值的连续原始索引合并，不跨被排除的片段。

窗口为长度归一化对角带 `abs(i/(N-1)-j/(M-1)) <= WindowRatio`，默认1不限制。
不同长度可比较；过窄而不可达时明确报错，不静默扩大。背景参考 [FMP DTW variants](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C3/C3S2_DTWvariants.html)。
窗口针对参与帧序号，不是原始毫秒。

特征预先缓存，局部成本每格计算一次，保留成本/累计矩阵与路径。默认最多4,000,000格，超出报错。
比较耗时含特征、质量、DTW和差异汇总，不含文件读取、报告序列化或GUI。后台支持取消。

## 调用与结果

```csharp
var store = new SignCoach.RecordingStore(referenceRoot);
var a = SignCoach.Comparison.SequenceComparer.Load(store, "hello", "take_001");
var b = SignCoach.Comparison.SequenceComparer.Load(store, "hello", "take_002");
var result = SignCoach.Comparison.SequenceComparer.Compare(a, b, new SignCoach.Comparison.ComparisonSettings());
// result.dtw：累计/归一化距离、路径、LocalCosts/Accumulated矩阵。
// result.quality_a/b：原始/可靠比例、缺失区间、参与帧数。
// result.similarity：有效段诊断指数，须同时检查 result.low_quality。
// result.differences：高差异 A/B 原始相对毫秒区间。
string report = result.ToJson();
```

结果示例 `Verification/comparison_example.json`。JSON导出路径、距离、参数、质量和分组统计，不导出大二维矩阵。
矩阵可在C#结果访问；界面为128×128采样热图。现有测试录制没有被升级为标准。
