# 第二阶段 TCP 协议与坐标

Python 为 TCP 服务端，默认 `127.0.0.1:5005`，Unity 为单个客户端。无鉴权、无公网服务。
Python 使用标准库 socket，Unity 使用后台线程 TcpClient。通信不包含图像，只有关键点 JSON。

## 帧格式

UTF-8，每个 JSON 对象后接一个 LF (`\n`)，即 JSONL；没有长度头，不把单次 recv 当成一帧。
JSON 结构直接来自第一阶段 `process_result()` / `to_json()`，没有新增协议字段。

```json
{"timestamp":156,"hands":[]}
```

有手时 hands 最多 2 项，各项有 handedness、handedness_score、landmarks；landmarks 为 21 个 id/x/y/z，id 为 0–20。
`timestamp` 是本次 Python 摄像头会话起点后的单调毫秒，不是 Unix 时间。
客户端重连后允许时间戳重新从较小值开始；每次连接内要求递增。
`handedness_score` 是模型左右手分类分数，不是关键点精度或动作评分。
Unknown 的 null 分数在 Unity JsonUtility 的数值字段中按缺省 0 处理，不改变 Python 原 JSON，也不据此纠正标签。
数组索引只用于分配复用绘制槽，语义始终读 handedness，允许实际模型偶尔产生两个相同标签。

## 传输与异常

- Python 不等 Unity：无客户端时仍采集和推理。启用 `--tcp` 才监听。
- 每次推理后尝试发送；所有网络 socket 均非阻塞。客户端断开时关闭该连接，下一帧重新尝试接受连接。
- 为避免慢接收拖住采集，最多保留未发完的一条及最新一条；已开始发送的 JSON 保证完整，不将半条替换。
  慢客户端可能跳过中间帧；当前消息超过 1 秒无法发送完时断开并等待重连，不累积无界队列。
- Unity 后台按字节拼到 LF 再解 UTF-8，支持粘包/拆包、CRLF、跨块 UTF-8；单行上限 64 KiB，超长行丢到下一换行再恢复。
- 不完整但未换行的内容只保留到后续字节到达，不会提前解析；断开时丢弃尾部。
- 解析异常、点数异常、重复/越界 id、非有限坐标或非递增时间戳的帧会拒绝，下一合法行仍可恢复。
- 后台只发布最新结果，由锁保护；Unity 对象只在主线程创建和更新，接收速度快于渲染时不排队播放旧帧。
- 空 hands、无效结果、断线会清除骨骼；超过 0.5 秒未有合法数据也清除，防止残留。
- Unity 未连上时显示 Connecting / retrying，连接失败/中断约每 0.5 秒重试，连接等待上限 1 秒。
- Unity 关闭/禁用时通知线程退出、关闭 Socket 以中止阻塞读取，并有限等待线程退出；不使用 Thread.Abort。
- 摄像头读取失败时 Python 保持原有报错并释放相机、模型、Socket；Unity 会检测断线并清除显示。

## 显示方向

JSON 的 x/y 来自原始、未镜像的摄像头图像，x 向右，y 向下；z 仍保留相对深度。
Python 的 OpenCV 镜像只用于自己的画面显示，不修改 JSON。
Unity 独立显示一个与摄像头同为 4:3 的镜像骨骼视口，使用：

```text
X = (0.5 - x) * 6.4
Y = (0.5 - y) * 4.8
Z = 0（本阶段只做二维调试显示，原始 z 仍在解析结果里）
```

视口保持宽高比，不随窗口比例拉伸骨骼。Unity 不再打开摄像头，没有 WebCamTexture 或第二次视频采集。
因此请将 Python 摄像头窗口与 Unity 骨骼窗口并排对照；Unity 当前没有摄像头视频背景。
左右标签不因镜像交换；只读取模型原标签，并采用 Left 绿色、Right 蓝色、Unknown 灰色。
真人位置、移动、遮挡和手移出画面的效果须由实际联合测试确认，静态坐标测试不能替代。
